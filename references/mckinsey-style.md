# McKinsey-style slides — the rules this skill follows

Distilled from "How to Build a McKinsey-Style PowerPoint with AI: 8 Simple Rules for Consulting-Grade Slides" (S. Chen, Jul 2026) and adapted to scientific conference talks. The style is not a colour scheme or a font; it is a communication discipline: the conclusion appears early, every slide has one job, evidence supports every claim, and each page can be understood in seconds.

A strong deck answers four questions: **What is the conclusion? What evidence supports it? Why does it matter? What should happen next?**

## Rule 1 — Storyline before slides
Write the answer in one sentence (governing thought). List the arguments that make it credible and put the strongest evidence under each: conclusion → supporting argument → evidence → implication / next step. Order the arguments so the audience can follow. The story must make sense when reading only the slide titles.

Scientific adaptation — a typical arc (adjust to the sources):
1. Title
2. Executive summary: the answer + 2–3 headline results
3. Why it matters (the problem, the gap)
4. Approach (data/experiment + method, one slide each at most)
5. Evidence slides (one result per slide, strongest first unless logic demands otherwise)
6. Limits and validity (brief, honest — this builds credibility with reviewers)
7. Implications / next steps
8. Take-home messages → closing slide

## Rule 2 — Every title is a conclusion (action title)
A topic title labels ("Sensitivity analysis"). An action title states what the slide proves ("Coating thickness, not temperature, dominates corrosion loss"). Good action titles are specific, supported on the same page, and readable in one pass (≤2 lines, ~8–15 words). Never write a conclusion the visual cannot support; correlation is not causation; don't generalise beyond the tested range.

Make titles **dynamic and result-oriented**:
- active voice with a strong verb (*cuts, doubles, outperforms, reproduces, identifies, removes the need for*), not nominal labels (*Analysis of…, Results of…, Overview*);
- lead with the result, then the cause ("Corrosion loss falls 40 % when the coating is doubled", not "Effect of coating thickness on corrosion");
- quantify when the source allows it — the number is the proof;
- speak the target journal's language (its scope terms), so the title answers the question its readers ask.
Dynamism never outruns the evidence: if the source hedges, the title hedges ("points to", "suggests"). Rigour lives in the method footnote, the axis titles and the source note — not in a dull title.

## Rule 3 — One primary task per slide
Before designing, finish the sentence: "The audience should leave this slide understanding that …". If the answer has several unrelated clauses, split the slide. This skill adds a hard cap: **at most three topics per slide**. Several objects are fine if all of them support the same title.

## Rule 4 — Match the visual form to the information relationship
| Relationship | Visual |
|---|---|
| Sequence / process / method pipeline | left-to-right flow with arrows |
| Repetition / loop | cycle |
| Levels / proportion | hierarchy, pyramid |
| Comparison of options | 2–3 columns, before/after |
| Ranking / categories | horizontal bar chart |
| Change over time | line chart |
| Contribution | waterfall or stacked bar |
| Relationship between variables | scatter / parity plot |
| Exact values matter | small table (≤5 rows) |
| One striking number | big-number callout with a short label |

Arrows mean direction, circles mean recurrence, pyramids mean level. A diagram whose geometry tells the wrong story weakens the slide.

## Rule 5 — Charts are evidence, not decoration
Identify the comparison that matters; remove series, labels and gridlines that don't help. One accent colour for the key evidence, neutral greys for context. Simplified charts must stay numerically defensible. Every important number gets a source note (file, table/figure/section). Keep a slide-to-source register — here, the storyboard's "Source" column.

Scientific adaptation — "simple" never means "undescribed". Every chart must be perfectly described:
- both axes titled with the **quantity and unit** in brackets or after a comma ("Flow velocity u [m/s]"); dimensionless quantities say so ("[–]" or "[%]");
- a legend or direct labels whenever more than one series is shown; the accent series is the one the title talks about;
- the axis range does not distort the message (bars start at zero; a truncated axis is marked);
- a source note naming the file and table/figure; a caption with the source figure number for placed images.

## Rule 5a — Clean main area, methodology in the footnote
The main area carries the message and its evidence only. Details a reviewer needs but the audience does not have to read — p-values, confidence intervals, n, SD, R²/RMSE with the validation scheme (e.g. k-fold or leave-one-out), fold counts, parameter or solver settings, test conditions — go into a small-type method footnote (10–11 pt, grey) directly above the source line, at most two lines. The headline number stays big; its statistical qualification sits in the footnote, and the speaker notes explain it in plain words.

## Rule 6 — Hierarchy through spacing, not decoration
- narrow title zone at the top, stable content grid, consistent margins,
- aligned chart and text edges,
- clear separation between evidence and implication (e.g. a "So what" box),
- restrained footer area: method footnote (small type) above the source line.
Size and position set the reading order: title → evidence → implication → method footnote/source. Contrast at least 4.5:1 for normal text and 3:1 for large text (projectors wash colours out). Avoid borders, shadows, decorative icons and colour used to hide an unclear hierarchy.

## Rule 7 — A small family of reusable page types
Cover/section · executive summary · argument-and-evidence · comparison · data chart · process/timeline · recommendation/next steps · (appendix). Each type has stable rules for title, columns, charts, notes and sources. Similar charts use the same colours and label conventions; comparable text blocks have comparable widths. Consistency ≠ one layout repeated everywhere.

## Rule 8 — Review in three separate passes
1. **Story** — read only the titles: do they reach a clear conclusion?
2. **Evidence** — validate every number, unit, date, calculation and source; every chart axis titled with its unit; statistics in the method footnote.
3. **Design** — alignment, spacing, typography, colour, export quality at presentation size.
A reviewer who did not build the deck should be able to state each slide's conclusion in a few seconds; confusion means a weak title, too much content or the wrong visual.

## Workflow summary
Define audience and desired outcome → one-sentence answer → supporting arguments → evidence and sources per argument → title storyline → layout per slide → charts/diagrams built around the claim → review story, evidence and design separately.
